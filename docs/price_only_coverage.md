# Price-data coverage by the market survey

**File:** `outputs/temp/price_only_coverage_summary.csv`
**Built by:** `dofiles/diagnose_price_only.py` (the coverage tally at the end of the price-only diagnosis)

This answers a specific question: of the price (PSPS-derived) data's `(province, municipality, item, nsu)`
cases that have no matching raw NSU in the market survey (MS) for that exact cell, how many can
nonetheless be converted using MS-observed weight data, and how many genuinely cannot?

---

## Numbers (current run)

| | n | of 949 |
|---|---|---|
| **Direct in-cell match** (`cause_label = harmonizable`) — the unit folds to a unit already present in that exact cell | 304 | 32% |
| **Resolved via in-cell fallback** — no direct match, but a weight-differentiated sibling is present in that exact cell (`fallback_harmonized_nsu_unit` non-blank) | 198 | 21% |
| **No MS presence in that cell at all — not even a fallback** | **447** | **47%** |

The 447 with no in-cell MS presence break down as:

| | n |
|---|---|
| `nonsensical (unmappable)` — no MS referent for the item anywhere; no weight at all (`harmonized_nsu_unit = .c`) | 66 |
| `nonsensical (recoverable)` — quantity-prefixed junk salvaged to a base unit by heuristic, not by MS match | 9 |
| `empty/uncommon`, item absent from the cell entirely | 136 |
| `empty/uncommon`, unit valid for the item elsewhere in MS, just not in this cell (or a fallback-eligible sibling) | 236 |

**Read this table by what it means for conversion, not just presence:**

- The **66** `nonsensical (unmappable)` rows are the only ones with *zero* usable weight — routed to `.c`.
- The **9** recoverable rows get a weight, but from a string-parsing heuristic (e.g. `14 tasa` → base unit
  `tasa`, count in `detail`), not from anything observed in MS.
- The **136 + 236 = 372** `empty/uncommon` rows still have a **usable weight** — `harmonized_nsu_unit`
  is never blank for cause 2 — but it comes from that unit's pool in *other* cells/provinces, not from
  this specific cell. "No MS presence in this cell" is not the same as "no weight available"; it means
  the conversion factor applied here is not locally anchored.

So depending on what "genuinely not present" is meant to capture:
- **Zero weight whatsoever:** 66 (the unmappable junk).
- **No MS observation anywhere in this exact cell, direct or fallback:** 447 (the number above) — most of
  these (372) still convert using a weight estimated elsewhere for the same item/unit.

## How to reproduce or recompute

From `outputs/temp/cases_in_price_not_in_MS_diagnosed.csv`:

```python
direct   = df.cause_label == 'harmonizable'
fallback = ~direct & (df.fallback_harmonized_nsu_unit != '')
none     = ~direct & ~fallback
```

`none` is the 447-row set. Its `nonsensical (unmappable)` / `nonsensical (recoverable)` /
`empty/uncommon` split further separates "no weight at all" from "weight from elsewhere, not this cell."

The tally is regenerated by `diagnose_price_only.py` every run and printed to console under
`=== price-only coverage summary ===`, and written to `outputs/temp/price_only_coverage_summary.csv` — so
these numbers stay in sync with the classifier automatically; this doc is a write-up of what they mean,
not a separate source of truth.
